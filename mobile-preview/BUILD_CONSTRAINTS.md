# 数理图解网站搭建约束

更新日期：2026-11-26。本文用于独立重建网站，也作为现有项目的功能与发布验收依据。

「数理图解」是一个面向高中数学和物理的手机网页。用户可以将原题和教材方法合成提示词，复制到自己选择的 AI 对话。需要演示时，把 AI 返回的 HTML 或模板 JSON 粘贴回网页，在当前设备上预览。

## 交付形式

- **单文件 HTML 版**交付 `index.html`，将样式、脚本、示例、方法卡数据和使用到的模板内联。双击打开即可生成提示词和运行课件。若浏览器限制本地剪贴板或存储，保留手动复制粘贴和当前会话内的编辑。单文件版支持离线运行，页面应标明离线模式的额度、兑换和管理功能不可用。
- **公开部署版**交付网页和同源额度 API，由持久化数据库保存计数、兑换状态和当前邀请码规则。使用 HTTPS，允许访客直接打开和使用。前端也可打包成单个 `index.html`。公开版的限额由后端执行，浏览器存储用于草稿和最近记录。

## 页面布局和使用流程

编辑页从上到下放置站名、简短用途说明、公开版额度状态、功能切换与当前操作区。首屏提供「运行代码」和「生成提示词」。宽屏编辑区居中，参考最大宽度 `640px`。窄屏单列，使用系统字体、浅色底、细边框和一种主强调色。可参考现有页面的背景 `#F5F5EF`、正文 `#1E3531` 与主按钮 `#146557`。

### 生成提示词

1. 提供原题输入、题型、AI 和回答方式。题型覆盖集合、逻辑与复数，函数、数列与不等式，几何与截面，解析几何与圆锥曲线，概率与统计，以及力学、电路与电磁场、光学、热学，并提供「让 AI 判断」。AI 选择包括 ChatGPT、DeepSeek、千问 / Qwen、豆包和通用选项。每个具体题型至少提供一道条件完整的自编试用题。
2. 支持「分步解题」和「解题与交互图解」。分步解题要求提取题设、解释方法依据、给出推导和结论，并做回代、边界、单位或事件顺序等与原题有关的复核。信息不足时指出具体缺口。解题与交互图解根据下文输入格式，要求交付一份 HTML 或一份适用的模板 JSON。
3. 方法卡按学科、教材和章节组织，覆盖有图和无图的知识点。每张卡写明适用条件、识别线索、步骤、易错点、相关变式与出处。允许手选，也可按原题推荐至多两张。只加入相关卡片的必要内容，并把原题单列为解题材料。方法卡未匹配时仍可生成提示词。
4. 输出放入可选择的只读文本框，提供「复制提示词」。选择交互图解时同时提供「去粘贴 AI 回复」。用户自行在 AI 对话中提交提示词与题图。网页本身在本地拼接提示词，无需模型 API 密钥。

### 题型、试用题和教材专题联动

- 切换题型后立即显示该题型的试用题。「让 AI 判断」展示全部试用题。切换时保留用户输入的原题，清除之前手选的专题和已经生成的旧结果，并重新计算推荐。
- 点选试用题时填入完整题干、设置对应题型，清除旧的手选专题，并同步刷新试用题列表与方法卡推荐。
- 选定题型但尚未输入题目时，在手选区域上方显示该题型的代表方法卡，标为「题型参考（输入题目后细化）」。输入或修改题目后，立即显示实际匹配的卡片标题，标为「按题目推荐」。这些反馈在点击生成按钮之前可见。
- 题目未匹配时明确提示。若展示题型参考卡，标为「题型参考（当前题目暂无匹配）」。仅作题型参考的卡片不自动附入提示词，用户可以主动手选。
- 手选下拉框按教材与章节分组，允许从实际提供的完整目录中选择一张卡。手选后显示「已手选方法卡」及标题，生成时采用该卡。切回「按题目自动推荐」后重新按题目匹配。
- 推荐展示、手选目录与最终提示词共用同一份卡片数据和选择逻辑。生成后显示实际附入的卡片名称。选择题型、查看推荐、填入试用题和手选专题均不扣次数。

### 方法卡随页面交付

单文件版和公开部署版都将本次交付的完整方法卡数据嵌入主页面。页面初始化时就能构建手选目录并计算推荐。手选能力不得依赖额外的卡片网络请求，也不得因自动推荐未匹配而禁用。独立的 `study/cards.json` 可用于数据核对，页面操作直接读取内嵌数据。

- 参考实现使用 `<script id="method-card-data" type="application/json">` 保存数据，通过 `textContent` 读取并用 `JSON.parse` 解析。序列化时将所有 `<` 转义为字面量 `\u003c`，防止内容闭合脚本标签。插入数据时避免字符串替换规则改写正文。
- 卡片至少保留唯一 `id`、学科 `subject`、标题 `title`、关键词 `keywords`、前提 `conditions`、步骤 `method`、误用 `pitfalls`、复核建议 `transferChecks` 与出处 `source`。分组需要时保留 `collection`、`chapter`、`category`，多来源卡保留 `relatedSources`。出处区分 PDF 页码、印刷页码、章节和课件页序。
- 卡片目录名称、数量与页面内实际数据一致。构建时检查数据非空、编号唯一、必要字段齐全及数据占位符已替换。缺失或损坏应在发布前修正，不能把空数组占位页面当作可交付成品。
- 只发布已提炼的方法卡和出处信息。教材原文、完整 PDF/PPT 和本机资料路径不作为页面依赖。

### 提示词中的解题约束

所有 AI 选项与两种回答方式都加入以下要求，原题材料单独放在提示词末尾。

1. 逐张核对候选卡的相关前提，标明「题设已知」「已推导」「尚缺条件」或「与题设不符」，给出题干依据或简短推导。缺条件时指出缺口或列出分支，不符合前提时换方法。
2. 在实际应用方法的步骤旁注明卡片编号、满足的前提和代入本题的式子。卡片未覆盖的步骤给出独立依据。
3. 将相关易错点转为本题检查，说明影响哪一步。从回代、端点和边界两侧、事件先后、另一种计算或原对象还原中选择适用检查，写明检查内容、做法和实际结果。
4. 仅验证特殊值时说明一般结论还需什么论证。变式建议保持为复核建议，不追加到原题条件。程序或交互未实际运行时注明未测。
5. 仅引用实际使用的卡片与所附出处，注明依据为方法卡。不得声称已经通读原书或原课件。文字题解保留条件依据、关键推导和验算，HTML 写入题解区，模板 JSON 使用已有字段表达。

各模型保留以下适配要求。

| AI 选项 | 提示词要求 |
| --- | --- |
| ChatGPT | 在聊天正文给出完整题解或可复制代码。图解交付适合复制回本站的完整 HTML / JSON |
| DeepSeek | 先独立求解，再对照已有解答。范围题验证端点和可取性，计数题还原原对象并去重，候选回代原式，中间计算使用精确值 |
| 千问 / Qwen | HTML 全部内联。几何元素共用坐标变换，检查真实交点、角标和垂直关系，验证 320px、390px 下标注可读及键盘连续操作，临界点与两侧分别验算 |
| 豆包 | 在正文交付。题图只使用能辨认的标注，看不清时具体说明缺少什么条件 |
| 通用 / 其他 | 使用共同的题型检查、方法卡前提核对和实际验算要求 |

### 运行图解

1. 接受直接粘贴的完整 HTML、模板 JSON，或含一个 HTML/JSON 代码块的 AI 回复。多个候选代码块由用户选一个。空输入、截断、格式错误和不支持的模板需提示修正。参考上限为题目 8,000 字符、课件 500,000 字符。
2. 提供「运行图解」「清空输入」和运动、电路、截面三个示例。输入校验通过且公开版扣次成功后才切换到预览。预览顶部显示标题、返回编辑和停止，底部提供重新运行和「图解有问题」。停止、返回和重跑均替换旧的预览环境，保留代码。
3. 可从校验错误、脚本报错或用户描述生成可复制的修复提示，交由用户粘回原 AI 对话。最近成功运行的课件最多保存三条，支持重新载入与清除。草稿保存在当前浏览器。存储失败时仍可使用编辑和预览。
4. 手机端主要触控目标至少 `44px`，输入框字号至少 `16px`，保留浏览器缩放和安全区。运行按钮在窄屏便于触达，软键盘出现时仍可使用。预览随可视高度变化，横竖屏均能返回或停止。表单有文字标签，键盘焦点和错误信息清楚可见。

## 可导入的课件格式

### 单文件 HTML

- 交付完整 HTML 文档，将 CSS、JavaScript、SVG 和所需数据内联。图片可用 `data:` 或 `blob:`。避免 CDN、远程脚本、外部字体、联网接口和依赖本地相对路径的资源。
- 页面讲清题设、关键推导和结论。主图设短标题，长公式、实时读数和图例放在图旁或下方。在 320–390 CSS 像素宽度下按单列排版，保持点名、刻度和按钮清楚。用线型、文字或符号辅助颜色区分。
- 依据题意选静态图、分步构造、参数拖动或时间动画。时间动画提供暂停、拖动、复位和必要的关键事件跳转。图形与读数使用同一模型，播放推进使用未舍入状态。用模型数值判定事件、边界和端点，区分有限时刻到达、逐渐趋近与演示截止。

### LessonSpec v1 模板 JSON

入口校验 `version`、`topic`、`problemText` 和 `givens`，再按题型校验字段与单位。数值由模板计算，可检查输入中的 `claims`。如果填写 `source`，应摘自该题题干。题设与模板不匹配时可交付完整 HTML。

| `topic` | 适用范围 | 核心已知量 |
| --- | --- | --- |
| `motion` | 一维恒加速度单阶段运动 | `v0`、`a`、`t`，单位依次为 `m/s`、`m/s²`、`s` |
| `circuit` | 理想直流电源与 1–8 个正电阻串联 | `voltage` 与 `resistors`，单位为 `V` 和 `Ω` |
| `section` | 受模板支持的标准实体截面，如正方体、长方体 | `solid`、`plane`、`unit`，包括实体尺寸和可确定的截平面 |

下面这份 JSON 可直接作为运动模板的验收输入，计算结果应为位移 `9 m`、末速度 `6 m/s`。

```json
{
  "version": 1,
  "topic": "motion",
  "title": "从静止开始的匀加速运动",
  "problemText": "物体从静止开始，以 2 m/s² 的恒定加速度沿直线运动 3 s。求位移和末速度。",
  "givens": {
    "v0": { "value": 0, "unit": "m/s", "source": "从静止开始" },
    "a": { "value": 2, "unit": "m/s²", "source": "2 m/s² 的恒定加速度" },
    "t": { "value": 3, "unit": "s", "source": "运动 3 s" }
  }
}
```

其他模板沿用同一外层结构，按 `topic` 替换 `givens`。

- `circuit` 可用 `{"voltage":{"value":60,"unit":"V"},"resistors":[{"value":10,"unit":"Ω"},{"value":20,"unit":"Ω"}]}`，总电阻应为 `30 Ω`，电流应为 `2 A`。
- `section` 可用 `{"solid":{"kind":"cube","a":2},"plane":{"points":[[2,1,0],[2,0,1],[1,0,2]]},"unit":"cm"}`。截平面为 `x+y+z=3`，与边长 `2 cm` 的正方体形成正六边形。

## 浏览器隔离和数据流

- 把用户粘贴的 HTML 放入独立的 `iframe`，使用 `sandbox="allow-scripts"` 并保持跨源隔离。父页面的标题、错误和历史记录使用纯文本写入。模板中的 JSON 按安全方式序列化后再嵌入，防止用户数据闭合脚本标签。
- 在用户内容前设置课件自己的 CSP，默认拒绝加载资源，按需允许内联脚本、内联样式和 `data:`/`blob:` 图片。限制网络连接、外部脚本、嵌套框架和表单提交。父页面接收诊断消息时，校验其来自当前预览框并匹配预期消息结构。
- 题目、课件、草稿和最近记录留在浏览器。额度 API 只传本次操作类别或用户主动提交的验证码。沙箱隔离页面权限，脚本死循环或资源耗尽仍可能卡住标签页。

## 公开版额度和邀请码

普通访客首次打开时由服务端签发匿名身份 Cookie。每个浏览器每天 20 次，「生成提示词」和「运行图解」共用额度，重新运行也占一次。北京时间 `Asia/Shanghai` 零点换日。查看额度、加载示例、切换题型、查看推荐、手选方法卡、复制提示词及输入校验失败均不扣次。不同标签页共享同一身份和计数。换浏览器、换设备或清除 Cookie 会建立新访客记录。

- 服务端用随机访客 ID 和签名识别身份。HTTPS 生产环境的 Cookie 设置 `Secure`、`HttpOnly`、`SameSite=Lax` 和 `Path=/`。服务端按访客和日期原子检查并递增，额度归零后返回 `429`。数据库或接口出错应提示重试，保留用户输入，额度查询和扣次结果禁止缓存。
- 兑换有效邀请码后，当前访客不限次。「管理员激活」用独立验证码建立有期限的管理会话，可不限次使用。会话绑定当前访客，具备管理员权限才可更换邀请码。新码保存后立即生效，旧码停止新兑换，已有兑换继续有效。
- 管理员验证码、初始邀请码和签名密钥由部署者通过服务端环境注入。使用恒定时间比较校验摘要，数据库保存当前邀请码的校验摘要。兑换和管理员激活设置尝试上限，更新操作校验同源。示例、前端和版本库只使用虚拟测试值。

以下接口与现站一致，独立重建也可采用等价契约。

| 请求 | 提交内容 | 行为 |
| --- | --- | --- |
| `GET /api/quota` | 无 | 初始化匿名会话并读取今日额度 |
| `POST /api/quota/use` | `action` 为 `run` 或 `prompt` | 普通访客原子扣次，返回剩余额度。不限次访客直接放行 |
| `POST /api/quota/redeem` | `code` | 校验当前邀请码并记录兑换 |
| `POST /api/quota/activate` | `code` | 校验管理员验证码并签发会话 |
| `POST /api/quota/invite` | `code` | 校验管理员会话后替换邀请码 |

状态示例为 `{"admin":false,"unlimited":false,"day":"2026-11-25","limit":20,"remaining":20}`。不限次时 `remaining` 为 `null`。未建立匿名会话时，前端先查状态取得 Cookie 再重试操作。扣次前完成输入校验，处理请求时暂时禁用重复提交。

## 验收清单

- [ ] 单文件版关闭网络后仍能打开、生成提示词并运行内置示例。公开版用全新浏览器直接打开，无需 ChatGPT 登录就能使用。
- [ ] 分别以同一份原题生成文字题解提示词和交互图解提示词。手选卡片保留适用条件和出处。空原题保留可编辑状态并提示补充。
- [ ] 切到「集合、逻辑与复数」只显示该类试用题，切到「力学」显示力学题，切回「让 AI 判断」显示全部。所有具体题型均有示例，切换不覆盖已输入原题。
- [ ] 空题目选「函数、数列与不等式」能看到题型参考；点「分段函数」后能看到按题目推荐的卡片。修改原题后同步更新，未匹配时给出明确状态。
- [ ] 主页面加载后，模拟独立卡片请求失败，仍能展开手选目录、选择「集合结论」并生成含 `math-01` 条件与出处的提示词。公开版保留正常额度接口，验证仅生成操作扣次。
- [ ] 遍历本次交付的全部卡片，核对目录数量、唯一编号和必要字段。含 `<`、脚本结束标签等内容经嵌入与解析后仍完整还原。
- [ ] 粘贴完整 HTML、上面的运动 JSON、以及带一个代码块的 AI 回复，各自能运行。多个代码块、无效 JSON 和不支持的模板给出具体提示并保留原输入。
- [ ] 在 320px 窄屏和手机横屏检查输入、软键盘、运行、返回、停止与重跑。验证键盘操作、手动复制粘贴及最近记录清除。
- [ ] 课件停止或退出后旧预览上下文已被替换。课件在隔离框内无法访问父页面数据，外链脚本及 `fetch` 等网络接口请求被拦截。
- [ ] 公开版混合执行两种有效操作共 20 次，第 21 次被阻止。并发提交也只放行 20 次。第二个独立访客仍有 20 次，跨北京时间零点后同一访客恢复为 20 次。
- [ ] 公开版访客兑换后不限次。管理员激活后能换码，普通访客和已兑换者都没有换码权限。换码后用新访客验证旧码失效、新码有效，原兑换状态继续有效。
- [ ] 从最终部署包实际返回的 HTML、脚本和内嵌数据执行推荐、手选和生成流程。发布后读取公开页面确认内嵌卡片与预期一致。记录浏览器和手机实测范围，未测项目明确标注。

## 构建与发布约束

单文件版将所需运行代码、示例、模板与方法卡全部内联，验收交付的 `index.html`。公开部署版按实际托管形式构建；复用本项目的 Worker 部署时，在 `mobile-preview` 目录运行：

```sh
node scripts/build-site.mjs
```

`scripts/build.mjs` 生成静态文件和内嵌方法卡，`scripts/build-site.mjs` 进一步生成 `dist/server/index.js`。线上 Worker 从该文件中的资源表返回页面与脚本。每次修改后都要重建完整 Worker，避免新静态文件与旧内嵌资源一起发布。

1. 核对本次使用的卡片数据集、教材分组和数量。主工作区与独立发布副本可能使用不同的 `vendor` 快照，按实际交付数据核验完整性。
2. 运行与变更相关的测试，再构建完整部署输出。用构建后的 Worker 请求 `/` 和前端脚本，核对页面内方法卡、手选选项和最终提示词一致。
3. 打包后检查归档中的 Worker、HTML 与入口脚本等于验证通过的输出。保存版本时使用对应源码提交和同一份归档，部署返回的已保存版本。
4. 部署成功后核对公开页面实际返回的内容。不能仅以版本号变化判定功能生效。对旧页面的验证需重新加载，并记录测试结果与未验证部分。

## 现有项目的参考实现

可用原生 HTML、CSS 和 JavaScript 实现。复用本仓库时，从 `mobile-preview` 目录查看前端 `src/`、课件编译器和示例 `vendor/solver-lab/lesson/`、额度模块 `worker/quota.mjs` 以及数据库迁移 `drizzle/0000_quota.sql`。现有公开版用 Worker 和 D1，构建入口为 `node scripts/build-site.mjs`，所需服务端绑定名为 `DB`、`QUOTA_SIGNING_KEY`、`QUOTA_INITIAL_INVITE`、`QUOTA_ADMIN_ACTIVATION`。使用其他托管平台时按同样的接口和会话规则实现即可。
